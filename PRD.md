## 1. Обзор

### 1.1. Проблема

Подготовка статьи по серии патоморфологических случаев занимает у практикующего патолога недели. Основное время уходит не на наблюдения, а на рутину:

- сведение разнородных данных (клиника, морфология, ИГХ, молекулярная генетика) в единую таблицу;
- статистический анализ, который патолог часто делает без поддержки биостатистика;
- поиск и сопоставление с литературой, формулировка новизны;
- адаптация текста под требования конкретного журнала (структура, лимиты, стиль цитирования, обязательные заявления);
- переоформление при переподаче в другой журнал после отказа.

### 1.2. Решение

Веб-приложение с AI-агентом, который ведёт автора от сырых данных до готовой к подаче рукописи и cover letter:

1. принимает и анонимизирует данные серии случаев;
2. проводит воспроизводимый статистический анализ и предлагает находки с объяснением логики;
3. сопоставляет находки с загруженной литературой и формулирует новизну;
4. генерирует статью по разделам под профиль выбранного журнала с согласованием каждого шага;
5. формирует cover letter и пакет сопроводительных документов.

### 1.3. Ключевые принципы продукта

| Принцип | Что это значит на практике |
|---|---|
| **Автор — главный** | Агент предлагает, автор решает. Ни один раздел, находка или цитата не попадает в рукопись без подтверждения. |
| **Числа считает код, а не LLM** | Все статистические результаты вычисляются в изолированной Python-среде. LLM только планирует анализ и интерпретирует результаты. |
| **Цитата = проверяемый фрагмент** | Любая ссылка на литературу привязана к конкретному фрагменту загруженного источника. Выдуманные источники исключены архитектурно. |
| **Честность выводов** | Малые выборки, множественные сравнения и разведочный характер анализа явно отражаются в интерфейсе и в тексте статьи. |
| **Privacy-first** | Персональные данные удаляются локально до любой передачи во внешнюю LLM. |
| **Прозрачность использования ИИ** | Система формирует AI-use statement в соответствии с ICMJE и политикой журнала. |

## 2. Пользователи

### 2.1. Персоны

| Персона | Описание | Ключевая потребность |
|---|---|---|
| **Практикующий патолог** (основная) | Врач-патологоанатом, есть интересная серия случаев, мало времени, английский B2–C1, базовая статистика | Быстро превратить данные в корректную статью для профильного журнала |
| **Молодой исследователь / аспирант** | Пишет первые статьи, не знает требований журналов | Структура, правильный стиль, подсказки по требованиям |
| **Руководитель группы** | Курирует несколько рукописей | Быстрая проверка черновиков, переподача в другой журнал |

### 2.2. Основные сценарии (Jobs to be done)

- **JTBD-1.** «У меня 12 случаев редкой опухоли с ИГХ и NGS — хочу понять, есть ли там что-то публикабельное».
- **JTBD-2.** «Данные и литература собраны — нужна статья под Histopathology».
- **JTBD-3.** «Статью отклонили в Modern Pathology — нужно быстро переоформить под Virchows Archiv».
- **JTBD-4.** «Нужен cover letter, который объясняет, почему статья подходит именно этому журналу».

## 3. Цели, метрики, не-цели

### 3.1. Цели продукта

1. Сократить время от готовых данных до черновика, готового к подаче, с недель до 1–3 дней работы автора.
2. Обеспечить соответствие рукописи требованиям журнала при первой подаче (без technical desk reject).
3. Исключить выдуманные цитаты и статистически некорректные утверждения.

### 3.2. Метрики успеха

| Метрика | Целевое значение (MVP → v1) |
|---|---|
| Доля цитат, прошедших автоматическую проверку привязки к источнику | 100% (жёсткое требование) |
| Доля утверждений с числами в Results, совпадающих с результатами анализа | 100% (жёсткое требование) |
| Время от загрузки данных до черновика всех разделов (активная работа автора) | ≤ 8 ч → ≤ 4 ч |
| Доля разделов, принятых автором после ≤ 2 итераций правок | ≥ 60% → ≥ 80% |
| Соответствие рукописи чек-листу журнала (автопроверка) | ≥ 95% пунктов |
| Технические отказы (desk reject по формальным причинам) у пользователей | < 5% |
| Утечки ПДн во внешние сервисы | 0 |

### 3.3. Не-цели (out of scope)

- Анализ цифровых изображений (WSI, морфометрия, CV-модели) — возможное направление v2+.
- Автоматическая подача рукописи в системы журналов (Editorial Manager, ScholarOne).
- Генерация «находок» без данных пользователя, написание обзоров литературы с нуля.
- Замена рецензирования, биостатистика или соавтора-эксперта: система — инструмент, ответственность за содержание несёт автор.
- Поддержка языков рукописи, кроме английского (в MVP).

## 4. Пользовательский путь (end-to-end)

```
[1] Создание проекта
     │  название/фокус, целевой журнал, тип статьи (original article / case series / brief report)
     ▼
[2] Загрузка данных ──► анонимизация ──► ручное подтверждение ПДн-отчёта
     ▼
[3] Структурирование ──► унифицированная карточка каждого случая ──► проверка автором
     ▼
[4] Анализ ──► находки с объяснением, уровнем доказательности, предложенными таблицами/графиками
     │         автор принимает / отклоняет / комментирует каждую находку
     ▼
[5] Литература ──► RAG-база ──► сопоставление находок с литературой ──► формулировка gap/новизны
     ▼
[6] Структура статьи ──► под профиль журнала ──► согласование
     ▼
[7] Генерация по разделам: Title → Abstract → Introduction → M&M → Results → Discussion → Conclusion
     │  каждый раздел: черновик → правки/комментарии → принятие → следующий
     ▼
[8] Проверки: цитаты, числа, лимиты, чек-листы (CARE/REMARK/STROBE), AI-disclosure
     ▼
[9] Cover letter + сопроводительные заявления
     ▼
[10] Экспорт: .docx по шаблону, таблицы, рисунки, список литературы, supplementary
```

Автор может вернуться на любой шаг; изменения на ранних шагах помечают зависимые разделы как устаревшие.

#### 2.2. Статистические ограничители (guardrails) — обязательны

| Размер серии | Разрешено | Запрещено / с предупреждением |
|---|---|---|
| **n = 2–4** | Только описательная статистика, сравнение случаев между собой, сопоставление с литературой | Любые тесты значимости, p-values, кластеризация |
| **n = 5–9** | Описательная статистика; точные тесты (Fisher) с пометкой «exploratory»; иерархическая кластеризация только как визуализация | Утверждения о значимости в Abstract и Conclusion; многофакторные модели |
| **n = 10–29** | Fisher, Mann–Whitney, Kruskal–Wallis, Spearman; KM при ≥ 5 событиях; кластеризация с оценкой устойчивости (bootstrap) | Многофакторная регрессия (кроме ≤ 1 ковариаты на ~10 событий) |
| **n ≥ 30** | Полный набор, включая χ², логистическую и Cox-регрессию с соблюдением правила EPV | — |

Дополнительно, независимо от n:

- **Поправка на множественные сравнения** (Benjamini–Hochberg FDR) по всему журналу проверенных гипотез; в интерфейсе показываются исходный p и q-value.
- **Размер эффекта с 95% ДИ** обязателен для каждой ассоциации (OR, разница медиан, ρ).
- Каждая находка получает **уровень доказательности**: `описательная` / `exploratory` / `статистически значимая после поправки`.
- Формулировки в тексте статьи автоматически согласуются с уровнем: exploratory-находки не описываются как установленные («suggests», «in this series», «warrants validation»).
- Тесты выбираются по типу данных из словаря (FR-1.11), а не по усмотрению LLM; LLM может предложить альтернативу только с обоснованием, которое видит автор.

#### 2.3. Формат карточки находки

```
Находка F-03                                         [exploratory]
─────────────────────────────────────────────────────────────────
Утверждение: В 6 из 7 случаев с мутацией GENE-X отмечена потеря
             экспрессии MARKER-Y (86% vs 13% в остальных, n=15).
Статистика:  Fisher exact p = 0.010; q (FDR) = 0.12;
             OR 42 (95% ДИ 2.1–830)
Литература:  ассоциация описана в 1 из 14 загруженных источников
             [Author 2023, с. 5] — на серии 4 случаев.
Новизна:     «Ассоциация редко упоминается в литературе»
Ограничения: малое n, широкий ДИ, не значимо после поправки;
             возможный вклад гистотипа (4 из 6 — вариант Z).
Иллюстрация: → Таблица 2x2, → oncoprint
Код анализа: [показать]
Действия:    [Принять] [Отклонить] [Комментировать] [Проверить иначе]
```

**Критерии приёмки модуля 2:**
- Все числа в карточках воспроизводятся повторным запуском сохранённого кода (100%).
- На синтетических наборах с заданными ассоциациями и шумом: заложенные эффекты выявляются; доля ложных «значимых» находок на чистом шуме не превышает заданного уровня FDR.
- При n < 5 система не выводит p-values ни в интерфейсе, ни в тексте.

### Модуль 3. Работа с литературой

| FR-3.8 | Автоматическая расстановка цитат в тексте: каждое утверждение со ссылкой привязано к конкретному фрагменту источника (grounding) | P0 |
| FR-3.9 | **Проверка цитат**: независимая проверка, что процитированный фрагмент действительно поддерживает утверждение; неподтверждённые цитаты подсвечиваются и блокируют экспорт до решения автора | P0 |
| FR-3.10 | Формирование списка литературы в стиле журнала через CSL (Vancouver, APA, NLM, AMA, Harvard и любые другие из репозитория CSL) | P0 |
| FR-3.11 | Проверка полноты: все загруженные источники использованы / список неиспользованных; нет ссылок вне базы; дубликаты | P0 |
| FR-3.12 | Предложение дополнительных источников: поиск в PubMed по теме находок с пометкой «рекомендовано к прочтению» — добавляются в базу только после загрузки/подтверждения автором | P1 |
| FR-3.13 | Проверка отозванных статей (Retraction Watch / Crossref) | P1 |
| FR-3.14 | Импорт из менеджеров ссылок (Zotero, EndNote, Mendeley — RIS/BibTeX) | P1 |

**Жёсткое правило:** агент не может сослаться на источник, которого нет в RAG-базе проекта. Упоминание «известных фактов» без источника допускается только как общее знание, без ссылки, и помечается для проверки автором.

**Критерии приёмки модуля 3:**
- 0 ссылок на источники вне базы проекта в любом сгенерированном тексте.
- Метаданные в списке литературы совпадают с PubMed/Crossref в 100% случаев, где источник там есть.
- Точность проверки поддержки цитаты (FR-3.9) на размеченном наборе ≥ 95% по выявлению неподтверждённых утверждений.

### Модуль 4. Профили журналов

#### 4.1. Принцип работы

1. Пользователь выбирает журнал из базы или вводит название.
2. Если журнал есть в базе — загружается актуальный профиль.
3. Если журнала нет — агент запрашивает URL страницы Author Guidelines или PDF, извлекает профиль и показывает его автору на подтверждение.
4. Профиль хранит **дату проверки и URL источника**; если с последней проверки прошло более 90 дней — система перепроверяет guidelines и сообщает об изменениях.

#### 4.2. Состав профиля журнала

| Параметр | Примеры |

| Лимиты | Слова: по разделам и суммарно (что входит в подсчёт); число таблиц, рисунков, ссылок; title (символы) |

| Таблицы и рисунки | Форматы файлов, разрешение (dpi), цветовой режим, требования к подписям, масштабные отрезки на микрофото, размещение (в тексте / отдельно) |
| Цитирование | Стиль (CSL), формат ссылок в тексте (числовые / автор-год), лимит числа ссылок |

### Модуль 5. Генерация статьи

#### 5.1. Входные данные

- Название статьи или описание контекста / фокуса публикации.
- Целевой журнал и тип статьи.
- Подтверждённые данные (модуль 1), принятые находки (модуль 2), литература (модуль 3).

#### 5.2. Процесс

1. **Находки.** Агент сводит принятые автором находки в основной нарратив (1–3 ключевых сообщения статьи).
2. **Новизна.** По литературе агент формулирует gap и новизну; автор подтверждает.
3. **Структура.** Агент предлагает план статьи под профиль журнала: разделы, ключевые тезисы каждого раздела, распределение таблиц и рисунков, бюджет слов. Автор согласует.
4. **Генерация по разделам:** Title (3–5 вариантов) → Abstract → Introduction → Materials & Methods → Results (с таблицами и рисунками) → Discussion → Conclusion.
5. **Цикл правок:** каждый раздел показывается автору → правки (прямое редактирование, комментарии к фрагментам, инструкции агенту) → принятие → следующий раздел.
6. **Финальная сборка:** Abstract пересобирается после финализации Results и Discussion, чтобы соответствовать итоговому тексту.

#### 5.3. Требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-5.1 | Генерация плана статьи и его согласование до генерации текста | P0 |
| FR-5.2 | Последовательная генерация разделов с циклом правок; редактор с комментариями к выделенному фрагменту и командами агенту («сократи до 250 слов», «усиль сравнение с [источник]») | P0 |
| FR-5.3 | Materials & Methods генерируется из фактических параметров: критерии отбора, методы ИГХ (клоны, разведения, платформы — запрашиваются у автора, если их нет в данных), молекулярные методы, статистика — **из журнала проведённых тестов** (FR-2.11) | P0 |
| FR-5.4 | Results: каждое число в тексте связано с результатом анализа; автоматическая сверка текста с результатами до экспорта | P0 |
| FR-5.5 | Discussion: интерпретация находок, сопоставление с литературой (только из RAG-базы), обязательный абзац ограничений (малое n, ретроспективный дизайн, отсутствие валидационной когорты и т.п.) | P0 |
| FR-5.6 | Таблицы: автогенерация «Таблицы 1» и таблиц находок в формате журнала; редактирование | P0 |
| FR-5.7 | Рисунки: графики из аналитического движка (тепловые карты, oncoprint, KM-кривые, box plots) в формате и разрешении журнала | P0 |
| FR-5.8 | Микрофотографии: загрузка автором, компоновка панелей (A, B, C…), генерация подписей (окраска, увеличение), проверка наличия масштабного отрезка и разрешения | P1 |
| FR-5.9 | Supplementary materials: полная таблица случаев, дополнительные таблицы, код анализа | P1 |
| FR-5.10 | Генерация обязательных заявлений: Ethics, consent, COI, funding, data availability, author contributions (CRediT — по вводу автора), **AI-use disclosure** | P0 |
| FR-5.11 | Заполнение чек-листа отчётности (CARE / REMARK / STROBE) с указанием, где в тексте выполнен каждый пункт | P1 |
| FR-5.12 | Пересборка затронутых разделов при изменении данных, находок или журнала | P1 |
| FR-5.13 | Экспорт: .docx по шаблону журнала (через Pandoc + reference-шаблон), отдельные файлы таблиц и рисунков, список литературы, также .md и LaTeX (P2) | P0 / P2 |

#### 5.4. Требования к качеству текста

- **Язык:** академический медицинский английский (UK или US — по профилю журнала).
- **Без AI-клише:** автоматический линтер по стоп-листу (например, «delve», «plays a pivotal role», «in the realm of», «it is worth noting», «a testament to», «navigating the complexities», «shed light on», избыточные «Furthermore/Moreover» в начале предложений) с подсветкой и предложением замены; стоп-лист пополняется.
- **Терминология:** корректная патоморфологическая номенклатура — классификация ВОЗ (актуальное издание), HGNC для генов, HGVS для вариантов, стандартная запись ИГХ-результатов; консистентность терминов по всей статье.
- **Нарратив:** от находок к интерпретации; каждый абзац Discussion привязан к конкретной находке.
- **Соответствие уровню доказательности:** формулировки не сильнее, чем позволяет статистика (см. 2.2).
- **Консистентность:** числа, аббревиатуры (расшифровка при первом упоминании), названия маркеров совпадают между Abstract, Results, таблицами и рисунками.

**Критерии приёмки модуля 5:**
- Автопроверка консистентности чисел: 0 расхождений между текстом, таблицами и результатами анализа на момент экспорта.
- Экспортированный .docx открывается в MS Word без ошибок и соответствует лимитам журнала.
- Экспертная оценка (≥ 2 патолога) на 5 тестовых проектах: терминология и научный стиль ≥ 4 из 5 по шкале оценки.

## 7. Интерфейс

### 7.1. Основные экраны

| Экран | Содержание |
|---|---|
| **Дашборд проектов** | Список проектов, статус (этап), целевой журнал, дата изменения |
| **Мастер проекта** | Боковая панель этапов 1–10 со статусами; основная область — текущий этап |
| **Данные** | Загрузка → отчёт анонимизации (подтверждение) → таблица «случаи × признаки» с подсветкой извлечённых/спорных значений → словарь данных |

| **Литература** | Список источников с метаданными и статусом (использован / не использован), матрица литературы, просмотр PDF с подсветкой цитируемых фрагментов |
| **Журнал** | Профиль журнала, дата проверки, чек-лист соответствия |
| **Редактор рукописи** | Структура слева, текст раздела по центру, справа — панель агента, комментарии, счётчики лимитов; клик по цитате открывает фрагмент источника, клик по числу — результат анализа |
| **Проверки перед подачей** | Сводный отчёт: цитаты, числа, лимиты, чек-листы, AI-клише, заявления; блокирующие и предупреждающие пункты |
| **Экспорт** | Пакет файлов и cover letter |

### 7.2. Принципы UX

- Прозрачность: везде, где агент сделал вывод, есть ссылка «почему» (данные, код, фрагмент источника).
- Прогрессивное раскрытие: статистические детали свёрнуты, но доступны в один клик.
- Цветовая кодировка уровня доказательности согласована во всём приложении.
- Блокирующие проблемы (неподтверждённые цитаты, расхождения чисел, неподтверждённая анонимизация) не позволяют экспортировать рукопись до решения автора.

### 8.2. Модель данных (ключевые сущности)

- **Project** — проект статьи: фокус, тип статьи, журнал, этап, настройки.
- **Case** — унифицированная карточка случая.
- **DataDictionary** — описание признаков.
- **AnalysisRun** — прогон анализа: код, версии, seed, результаты.
- **Hypothesis / Finding** — проверенная гипотеза / находка: метод, статистика, уровень доказательности, статус (принята/отклонена).
- **Source** — источник литературы: метаданные, файл, фрагменты (Chunk).
- **Citation** — связь «утверждение в тексте → фрагмент источника» + статус проверки.
- **JournalProfile** — профиль журнала с версией, датой проверки и URL источника.
- **ManuscriptSection** — раздел рукописи с версиями, комментариями и зависимостями.
- **CoverLetter**, **Statement** (этические и прочие заявления).

### 8.3. Агентная логика

- **Оркестратор** — LLM с tool use, работающая по явному графу этапов (не свободный цикл): каждый этап имеет вход, выход, критерии завершения и точку подтверждения автором.
- **Инструменты агента:**
  - `extract_case_fields` — извлечение данных в схему;
  - `run_analysis(spec)` — запуск анализа в песочнице по декларативной спецификации (тест, переменные, подгруппы); код генерируется из шаблонов, свободный код — только с показом автору;
  - `search_literature(query)` — поиск по RAG-базе проекта;
  - `verify_citation(claim, chunk)` — проверка поддержки утверждения фрагментом;
  - `fetch_metadata(doi|pmid)`;
  - `get_journal_profile(journal)`;
  - `render_figure(spec)`, `render_table(spec)`;
  - `check_manuscript(section)` — лимиты, консистентность чисел, AI-клише, терминология.
- **Модели:** Claude Opus 5.5 — планирование анализа, интерпретация, генерация текста; Claude Sonnet 5 / Haiku 4.5 — извлечение данных, проверка цитат, линтинг. Выбор моделей конфигурируется.
- **Рассуждения:** для каждой находки и ключевого решения сохраняется краткое объяснение логики, показываемое автору (данные → метод → результат → интерпретация → альтернативные объяснения).
- **Проверка генерации:** независимый проход-верификатор (другая модель или другой промпт) для чисел и цитат перед показом раздела автору.

## 9. Риски и меры

| Риск | Вероятность | Влияние | Меры |
|---|---|---|---|
| Выдуманные или искажённые цитаты | Высокая без мер | Критическое (репутация автора, ретракция) | Цитирование только из RAG, привязка к фрагменту, независимая проверка, блокировка экспорта |
| Ложные находки на малых сериях (p-hacking) | Высокая | Критическое | Guardrails по n, FDR, журнал всех гипотез, согласование формулировок с уровнем доказательности |
| Утечка ПДн | Средняя | Критическое (юридическое) | Локальная анонимизация, ручное подтверждение, провайдер с ZDR, шифрование, аудит исходящих запросов |
| Устаревшие требования журналов | Высокая | Среднее | Дата/URL в профиле, регулярная перепроверка, чек-лист перед подачей |
| Ошибки извлечения данных из неструктурированных заключений | Средняя | Высокое | Подсветка извлечённых значений, ссылки на источник, обязательная проверка таблицы автором |
| Текст звучит «как ИИ», отказ журнала | Средняя | Среднее | Линтер AI-клише, стиль под журнал, правки автора как основной цикл |
| Политики журналов по ИИ ужесточатся | Средняя | Среднее | AI-use disclosure, позиционирование как инструмента, а не автора; мониторинг политик |
| Некорректная терминология | Средняя | Высокое | Нормализация по ВОЗ/HGNC/HGVS, словари, экспертная валидация |
| Стоимость LLM выше ожидаемой | Средняя | Среднее | Маршрутизация по моделям, prompt caching, лимиты на проект, мониторинг |

## 10. План релизов

### Этап 0 — Прототип (4–6 недель)
- Загрузка .xlsx/.csv, анонимизация с подтверждением, унифицированная таблица.
- Описательная статистика, Fisher/Mann–Whitney с guardrails, карточки находок.
- Простой веб-интерфейс.
- **Цель:** проверить на 3–5 реальных сериях, находит ли агент ценное и понятны ли его объяснения.

### Этап 1 — MVP (P0, ~3 месяца)
- Модули 1–3 и 5–7 в объёме P0; профили журналов стартовой базы (модуль 4, P0).
- Редактор рукописи с циклом правок, проверки перед подачей, экспорт .docx.
- Cover letter.
- **Цель:** автор проходит путь от данных до готовой к подаче рукописи.

### Этап 2 — v1 (P1)
- Анализ выживаемости, сравнение с литературой на уровне находок, матрица литературы.
- Микрофотографии и панели, supplementary, чек-листы CARE/REMARK/STROBE.
- Переподача в другой журнал, зависимости разделов, перепроверка профилей.
- Импорт из Zotero/EndNote, проверка отозванных статей.

### Этап 3 — v2 (P2)
- Совместная работа, SSO, организации.
- Response to reviewers.
- Экспорт LaTeX, общая модерируемая база профилей журналов.
- Исследование: анализ WSI / цифровая патология.

## 11. Открытые вопросы

1. **Юрисдикция и хостинг:** где размещаются данные (РФ / ЕС / on-premise для учреждений)? Это определяет выбор LLM-провайдера и архитектуру анонимизации.
2. **Модель распространения:** SaaS для частных лиц, лицензия для учреждений, on-premise?
3. **Режим case report (n = 1):** входит в MVP или нет?
4. **Экспертная валидация:** кто из патологов участвует в оценке качества (минимум 2 эксперта) и в верификации профилей журналов?
5. **Бюджет на LLM** на одну статью и ценовая модель для пользователя.
6. **Интеграции:** нужен ли импорт из ЛИС (лабораторных информационных систем) учреждений?
7. **Исходное ТЗ:** в модуле 4 после стартового списка журналов были пустые пункты — предполагались ли дополнительные журналы или требования?

## 12. Глоссарий

| Термин | Определение |
|---|---|
| ИГХ | Иммуногистохимия |
| FISH | Флуоресцентная гибридизация in situ |
| NGS | Секвенирование нового поколения |
| CNV | Вариации числа копий |
| VAF | Доля аллеля с вариантом (variant allele frequency) |
| RAG | Retrieval-Augmented Generation — генерация с опорой на найденные фрагменты базы знаний |
| Grounding | Привязка утверждения в тексте к конкретному фрагменту источника |
| FDR | False Discovery Rate — доля ложных открытий; поправка Benjamini–Hochberg |
| EPV | Events per variable — число событий на переменную в регрессионной модели |
| CSL | Citation Style Language — открытый формат описания стилей цитирования |
| CRediT | Таксономия вклада авторов |
| ICMJE | International Committee of Medical Journal Editors |
| CARE / REMARK / STROBE | Руководства по отчётности: клинические случаи / исследования прогностических биомаркеров / наблюдательные исследования |
| ZDR | Zero data retention — провайдер не хранит данные запросов |
| WSI | Whole slide image — цифровой скан гистологического препарата |
