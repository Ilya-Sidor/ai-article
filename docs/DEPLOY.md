# Развёртывание AI Article (MVP)

## Состав

| Сервис | Что делает | Сеть |
|---|---|---|
| `caddy` | TLS 1.2/1.3 с автоматическими сертификатами, reverse proxy | наружу (443) |
| `api` | FastAPI: REST API + веб-интерфейс | internal + egress |
| `worker` | фоновые задачи из очереди в PostgreSQL (`python -m app.worker`) | internal + egress |
| `db` | PostgreSQL 16 + pgvector: пользователи, сессии, доступ, задачи, журнал обращений к LLM | только internal |
| `sandbox` | выполнение скриптов анализа; только numpy/pandas/scipy, read-only, без интернета | только internal |
| `grobid` | разбор PDF статей в TEI (разделы, страницы) | только internal |

Сеть `internal` объявлена `internal: true` — у БД, песочницы и GROBID нет маршрута в интернет. В
интернет выходят только `api`/`worker` (Claude API, PubMed, Crossref, Unpaywall).

## Запуск

```bash
cp .env.example .env    # заполнить: DOMAIN, POSTGRES_PASSWORD, SANDBOX_TOKEN, AI_ARTICLE_MASTER_KEY, ANTHROPIC_API_KEY
docker compose up -d --build
```

Первый зарегистрированный пользователь становится администратором (редактирует профили стартовой базы
журналов). Затем закройте регистрацию: `AI_ARTICLE_REGISTRATION=closed`.

## Ключи и резервные копии — обязательно

* **Мастер-ключ** (`AI_ARTICLE_MASTER_KEY`) шифрует ключи проектов. Без него данные проектов
  невосстановимы. Храните его в менеджере секретов и в резервной копии **отдельно** от данных.
* Резервные копии: том `appdata` (зашифрованные файлы проектов — можно хранить у стороннего провайдера)
  и дамп PostgreSQL (`pg_dump`: пользователи, доступы, журнал обращений к LLM).
* Удаление проекта уничтожает его ключ (crypto-shredding): копии зашифрованных файлов в бэкапах после
  этого не расшифровать.

## Требования PRD и как они закрыты

| Требование | Реализация |
|---|---|
| NFR-1 шифрование, удаление по запросу | AES-256-GCM, ключ на проект, обёрнутый мастер-ключом; путь файла — associated data; crypto-shredding при удалении |
| NFR-3 провайдер LLM без хранения данных | условие договора с провайдером; в LLM не уходят строки данных пациентов (см. README) |
| NFR-4 TLS 1.2+, шифрование при хранении | Caddy (`protocols tls1.2 tls1.3`), HSTS; см. NFR-1 |
| NFR-5 аутентификация, 2FA, изоляция | scrypt, сессии в HttpOnly-cookie (в БД только хэш), TOTP (RFC 6238, без повторного использования кода), блокировка после 5 неудачных попыток, CSRF-заголовок, доступ к проекту только по членству (default deny), роли owner/editor/commenter |
| NFR-6 песочница без сети | отдельный контейнер `sandbox`: internal-сеть, read-only, cap_drop ALL, лимиты памяти/CPU/PID, токен |
| NFR-7 логи без содержимого | журнал обращений к LLM: время, проект, задача, модель, объём; audit — действия без значений данных |
| NFR-14 долгие операции | очередь задач в PostgreSQL, отдельный worker, прогресс в интерфейсе, продолжение после перезагрузки страницы |
| NFR-15 evals | `python -m evals.anonymization_eval`; регрессионный порог в `tests/test_evals.py` |

## Что не проверено в этой сборке

Образы и `docker compose` не собирались: на машине разработки нет Docker. Код, который они запускают,
покрыт тестами (включая прогон всего набора на PostgreSQL 16 + pgvector и режим песочницы `http`), но
сборку, сети compose, TLS и GROBID-контейнер нужно проверить при первом развёртывании.

## Открытые решения (PRD, раздел 11)

* **Юрисдикция и хостинг** (РФ / ЕС / on-premise) — определяет, где стоит сервер и какой LLM-провайдер
  допустим. Для РФ-пользователей Claude API доступен не напрямую; compose-файл одинаков для всех
  вариантов, меняется только площадка и договор с провайдером.
* **Эмбеддинги для pgvector** — нужен провайдер (внешний API или локальная модель); до решения поиск по
  литературе остаётся лексическим (BM25).
