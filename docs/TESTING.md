# Как протестировать AI Article

Время: 1–1,5 часа на полный путь (без ИИ — около 20 минут). Всё делается в браузере.

## 0. Что понадобится

* Этот Mac включён (приложение работает на нём).
* Аккаунт Google — для бесплатного ключа Gemini (шаг 3). Из РФ — с включённым VPN.
* Тестовые файлы (уже лежат в папке `Desktop/Ai Article/samples`):

| Файл | Что это | Что проверяет |
|---|---|---|
| `samples/gist_series.xlsx` | 24 **вымышленных** случая ГИСО с «персональными данными» (ФИО, телефоны, СНИЛС, номера историй и блоков, даты, текст заключений) | анонимизацию, весь путь на малой серии (n = 24) |
| `samples/public/gist_msk_2023_quick.xlsx` | 60 **реальных обезличенных** пациентов с ГИСО | анализ на реальных данных, быстро (~15 с) |
| `samples/public/gist_msk_2023_all.xlsx` | все 469 пациентов того же исследования | анализ на большой серии (~1 мин) |
| `samples/gist_small_n4.csv` | 4 вымышленных случая | ограничители при n < 5 (p-values не показываются) |

Реальные данные: исследование «Gastrointestinal Stromal Tumors (MSK, Clin Cancer Res 2023)», PMID 37477937,
открытая база cBioPortal (cbioportal.org, study `gist_msk_2023`). Признаки: возраст, пол, локализация, тип
образца, размер, митозы на 50 ПЗБУ, группа риска, стадия, мутации KIT (с экзоном), PDGFRA (с экзоном),
SDH, NF1, TP53, число мутаций, рецидив и безрецидивная выживаемость, смерть и общая выживаемость. ИГХ в
этом наборе нет. При публикации результатов на этих данных нужно цитировать исходную работу и cBioPortal.
Файлы пересоздаются командой `python samples/build_public_gist.py`.

## 1. Куда заходить

* **На этом Mac — всегда работает:** http://127.0.0.1:8765 (добавьте в закладки).
* С другого устройства — публичный адрес вида `https://…serveousercontent.com`. Он может меняться при
  переподключении туннеля; актуальный записан в файле `~/ai-article-data/public_url.txt`. При первом
  заходе serveo показывает страницу-предупреждение — нажмите «Continue to Site».
* Файлы с настоящими данными пациентов загружайте только через локальный адрес.

## 2. Регистрация (один раз)

1. Откройте адрес → «Создать аккаунт».
2. E-mail, пароль (не короче 10 символов) и **код установки** — он в файле `~/ai-article-data/setup_code.txt`
   (его также присылал ассистент в чате).
3. Первая учётная запись становится администратором; ей переходят уже существующие проекты
   («Демо: ГИСО…» и «Миксома тест»). После этого регистрация закрыта для всех.
4. Рекомендуется: «Аккаунт» (e-mail справа сверху) → «Включить 2FA» → отсканировать QR-код приложением
   (Google Authenticator, Яндекс Ключ и т. п.) → ввести код.

## 3. Подключение ИИ (бесплатно: Gemini + OpenRouter)

Приложение использует цепочку бесплатных моделей: запрос идёт к самой сильной модели, у которой не
исчерпан дневной лимит, при исчерпании — к следующей. Чем больше ключей, тем длиннее цепочка.

1. **Gemini:** https://aistudio.google.com/apikey → войдите в Google → «Create API key» → скопируйте ключ.
2. **OpenRouter:** https://openrouter.ai → войдите (Google/GitHub) → https://openrouter.ai/settings/keys →
   «Create API Key» → скопируйте. Затем https://openrouter.ai/settings/privacy — разрешите бесплатные
   эндпоинты (переключатели про free models / training), иначе бесплатные модели не отвечают.
3. В приложении: «Аккаунт» → блок «ИИ-модели» → режим «Бесплатная цепочка: Gemini + OpenRouter» →
   вставьте оба ключа → «Сохранить» → «Проверить подключение».
4. Справа сверху появится модель, которая ответит первой.

Лимиты: у Gemini — по каждой модели отдельно (у сильнейших ~20 запросов в день, обновление в 10:00 МСК),
у OpenRouter — 50 запросов в день на аккаунт (обновление в 03:00 МСК; 1000 в день после разового
пополнения на $10). Полный путь по статье — примерно 60–100 запросов. Если все лимиты исчерпаны,
приложение так и скажет — продолжите на следующий день. Долгие операции идут в фоне: страницу можно
обновлять.

## 4. Сценарий A — анонимизация и анализ (без ИИ, ~15 минут)

1. «Проекты» → «Новый проект»: название любое, журнал — «Histopathology», тип — Case series → «Создать».
2. Шаг «Загрузка данных»: перетащите `samples/gist_series.xlsx`.
3. Проверьте отчёт об анонимизации. **Ожидается:** удалены столбцы ФИО, Телефон, СНИЛС, дата рождения;
   номера историй болезни и блоков заменены на PT-…/BLK-…; даты операции и контакта превращены в
   «мес. от индексной даты»; в тексте «Заключение» ФИО пациента и врача, телефон, номер ИБ, блок и дата
   заменены метками; точный возраст помечен как квазиидентификатор. Раскройте «Таблица после
   анонимизации» — персональных данных там быть не должно.
4. Поставьте галочку «Я проверил(а)…» → «Подтвердить анонимизацию».
5. Шаг «Структурирование»: таблица 24 случаев; вкладка «Словарь данных» — типы признаков
   (бинарный / категориальный / порядковый / количественный). Двойной клик по ячейке — правка значения.
6. Шаг «Анализ» → «Запустить анализ» (~10 с). **Ожидается:** баннер «Малая серия (n = 10–29)»; среди
   находок — взаимоисключение KIT/PDGFRA, связь CD117 с PDGFRA, корреляция митозов и Ki-67, связь митозов
   с рецидивом; у каждой — статистика, p и q (FDR), размер эффекта с 95% ДИ, ограничения, график, код.
7. Примите 2–3 находки («Принять»), одну отклоните, к одной оставьте комментарий.
8. Вкладки «Таблица 1», «Паттерны» (кластеризация, oncoprint), «Журнал гипотез» — все проверенные тесты,
   включая незначимые.
9. «Скрипт анализа (.zip)» — архив для воспроизведения анализа.
10. Дополнительно: новый проект с `samples/gist_small_n4.csv` — анализ должен выдать только описательную
    статистику, без p-values.

## 5. Сценарий B — реальные данные и ИИ

1. Новый проект «ГИСО MSK 2023», журнал — «Diagnostic Pathology», тип — Original article.
2. Загрузите `samples/public/gist_msk_2023_quick.xlsx` (или `_all.xlsx`) → подтвердите анонимизацию
   (персональных данных в файле нет — отчёт почти пустой, это правильно).
3. «Анализ» → запустить. **Ожидается:** «Полный набор (n ≥ 30)»; значимые находки вроде: PDGFRA-мутации
   чаще в желудке, KIT и PDGFRA взаимоисключаются, размер и митозы связаны с рецидивом.
4. С ИИ: у любой находки «Интерпретация ИИ» → альтернативные объяснения и ограничения; числа, которых нет
   в карточке, подсвечиваются. Вкладка «Свой вопрос»: например «Связана ли мутация PDGFRA с локализацией в
   желудке?» → «Разобрать вопрос» → «Проверить гипотезу».
5. Примите 3–4 находки, которые хотите видеть в статье.

## 6. Литература

1. Шаг «Литература» → «Источники» → в поле DOI/PMID вставьте (по одному в строке):
   ```
   37477937
   34326133
   36188659
   39064037
   26942271
   37120571
   ```
   Все шесть — с полным текстом в PubMed Central. Первый — исходная работа ваших данных.
2. У каждого источника: метаданные «✓ PubMed», текст «PMC full text». Кнопка «Извлечь» (ИИ) — тезисы с
   цитатами; вкладка «Матрица» — сводка по источникам и вашей серии.
3. «Поиск по базе»: например `PDGFRA gastric epithelioid`.
4. «Находки × литература» → «Сопоставить с литературой» у принятой находки. **Ожидается:** статус
   (описано / противоречит / не описано), цитаты с дословными выдержками и отметкой проверки, отброшенные
   непроверяемые цитаты, формулировка новизны. Примите подходящие цитаты, подтвердите новизну.
5. «Список литературы»: смените стиль (Vancouver, AMA, APA…) — оформление меняется.

## 7. Профиль журнала

1. Вверху «Журналы» → «Diagnostic Pathology».
2. В браузере откройте https://link.springer.com/journal/13000/submission-guidelines ,
   выделите всё (⌘A), скопируйте (⌘C), вставьте в поле «Текст Author Guidelines» → «Сохранить текст».
   (Сайты издателей не отдают страницы программе напрямую, поэтому текст копируете вы.)
3. «Извлечь профиль из guidelines» (ИИ). **Ожидается:** поля с цитатами из guidelines; зелёные — цитата
   найдена, красные — нет (исправьте вручную или отметьте «нет в guidelines»).
4. В поле «CSL-стиль» подставьте предложение `diagnostic-pathology`. Сохраните, подтвердите профиль.
5. В проекте, шаг «Проект» → «Целевой журнал» → Diagnostic Pathology → «Выбрать журнал».
   Шаг «Структура статьи» покажет разделы и лимиты журнала.

## 8. Статья (шаг «Генерация разделов»)

1. «1. Терминология» → «Перевести автоматически» → проверьте английские термины → «Сохранить».
2. «2. Данные автора»: заполните что знаете (учреждение, период, этика, авторы и роли). Для публичных
   данных MSK достаточно тестовых значений.
3. «3. План» → «Сгенерировать план» → отредактируйте → «Согласовать план».
4. «5. Разделы»: по очереди Introduction → Methods → Results → Discussion → Conclusion:
   «Сгенерировать» → «Просмотр» (числа подсвечены — они подставлены из анализа) → «Проверки» (замечания)
   → при желании «Инструкция агенту» (например, «сократи до 300 слов») → «Принять раздел».
   Затем Abstract и Statements.
5. «6. Название и ключевые слова» → «Предложить варианты» → выберите название → «Сохранить».

## 9. Cover letter, проверки, экспорт

1. Шаг «Cover letter»: заполните автора для переписки → «Написать cover letter» → проверьте
   требования журнала (галочки) → «Принять письмо».
2. Шаг «Проверки»: «Чек-лист журнала» и «Этика и прозрачность» (заявление об использовании ИИ,
   k-анонимность supplementary, заимствования).
3. Шаг «Экспорт»: «Скачать черновик (.zip)» — manuscript.docx, рисунки, supplementary, cover letter.
   «Пакет для подачи» доступен только когда блокирующих пунктов нет.

## 10. На что обратить внимание и как сообщить о проблеме

Проверьте, что:
* числа в тексте статьи совпадают с карточками находок и Таблицей 1;
* цитаты ведут на реальные фрагменты источников (клик по источнику, «Фрагменты»);
* формулировки для exploratory-находок осторожные («suggests», «in this series»);
* тексты ИИ по существу верны для патоморфолога — это главное, что автоматические тесты проверить не могут.

О проблеме пишите в чат: шаг, что делали, что ожидали, что получили (скриншот поможет).

## Если что-то не работает

* Страница не открывается по публичному адресу — используйте http://127.0.0.1:8765; адрес туннеля мог
  смениться (см. `~/ai-article-data/public_url.txt`).
* «ИИ-функции отключены» — проверьте ключ в «Аккаунт → ИИ-модели» → «Проверить подключение».
* «Исчерпаны дневные лимиты» — бесплатные тарифы; добавьте ключ OpenRouter или продолжите на следующий день.
* Сервер и туннель перезапускаются сами; после перезагрузки Mac запускаются автоматически.
