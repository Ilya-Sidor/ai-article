# AI Article — AI-агент для научных статей по патоморфологии

Реализация **Этапа 0 «Прототип»** из [PRD.md](PRD.md) (раздел 10) и **модуля 3 «Работа с литературой»**:
от сырых данных серии случаев до проверенных находок, сопоставленных с литературой автора. Автор проходит путь
загрузка → анонимизация с подтверждением → таблица «случаи × признаки» → анализ с карточками находок →
база литературы → новизна и цитаты, привязанные к фрагментам источников.

Ключевые принципы PRD, которые соблюдаются уже в прототипе:

| Принцип | Как реализовано |
|---|---|
| Числа считает код, а не LLM | Вся статистика — в `sandbox_lib.py`, выполняется в отдельном изолированном процессе Python. LLM только сопоставляет вопрос с признаками и интерпретирует готовую карточку; числа в ответе LLM, которых нет в карточке, подсвечиваются. |
| Воспроизводимость | Каждый прогон сохраняет самодостаточный `analysis.py` + `analysis_data.csv` + версии библиотек и seed. Приложение получает числа, выполняя **именно этот скрипт**; тест проверяет побайтовое совпадение при повторном запуске. |
| Честность выводов | Guardrails по n (2–4 / 5–9 / 10–29 / ≥30), FDR Benjamini–Hochberg по журналу всех гипотез, размер эффекта с 95% ДИ, уровни доказательности, формулировки согласованы с уровнем. При n < 5 p-values не выводятся нигде. |
| Privacy-first | Анонимизация ru/en на сервере; исходный файл не сохраняется; запросы к Claude заблокированы до подтверждения отчёта автором; в LLM уходят только названия/типы признаков и итоговые статистики; журнал исходящих запросов пишет только метаданные. |
| Цитата = проверяемый фрагмент | Агент видит литературу только через инструмент `search_literature` и ссылается на `chunk_id` + дословную выдержку. Код отбрасывает несуществующие фрагменты и неточные выдержки (без нечёткого сравнения: изменённое число или «not» не проходят), затем цитату независимо проверяет другая модель. Метаданные списка литературы — только из PubMed/Crossref. |
| Автор — главный | Отчёт анонимизации подтверждается вручную; каждая находка принимается/отклоняется/комментируется; словарь данных и значения в таблице редактируются; всё пишется в журнал аудита. |

## Быстрый старт

Нужен Python ≥ 3.10 (проект проверен на 3.12).

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
```

```bash
.venv/bin/uvicorn app.main:app --app-dir backend --port 8000
```

Откройте http://localhost:8000 и зарегистрируйтесь. **Первый зарегистрированный пользователь становится
администратором и владельцем проектов, созданных до появления аккаунтов.** Для демо загрузите
`samples/gist_series.xlsx`.

Данные проектов хранятся зашифрованными (AES-256-GCM). Локально мастер-ключ создаётся в
`~/.ai-article/master.key` — **сделайте его резервную копию: без него данные не расшифровать.** В
продакшене ключ задаётся переменной `AI_ARTICLE_MASTER_KEY`. БД по умолчанию — SQLite
(`data/app.db`); PostgreSQL — через `AI_ARTICLE_DATABASE_URL`. Развёртывание: [docs/DEPLOY.md](docs/DEPLOY.md).

ИИ-функции включаются, если SDK находит учётные данные Claude API (`ANTHROPIC_API_KEY` или профиль
`ant auth login`).

Тесты (SQLite) и тот же набор на PostgreSQL 16 + pgvector (встроенный сервер из пакета `pgserver`):

```bash
cd backend && ../.venv/bin/python -m pytest -q
```

```bash
cd backend && AIA_TEST_DATABASE_URL="postgresql+psycopg://…" ../.venv/bin/python -m pytest -q
```

Evals анонимизации (NFR-15): `cd backend && ../.venv/bin/python -m evals.anonymization_eval`.

## Что реализовано (соответствие PRD)

**Модуль 0.** FR-0.1 создание проекта (фокус, журнал из стартовой базы, тип статьи), FR-0.2 хранение артефактов,
FR-0.7 журнал аудита.

**Модуль 1 — данные.** FR-1.1 загрузка .xlsx/.csv/.tsv/.json (несколько файлов, объединение по внутреннему ID
истории болезни); FR-1.2/1.3 анонимизация ru/en: ФИО (в т.ч. «Иванов И.И.», «И.И. Иванов», по отчеству,
после «пациент/больная/врач»), даты, телефоны, e-mail, СНИЛС, полисы, паспорта, адреса, номера ИБ и блоков →
внутренние ID; FR-1.4 даты → интервалы от индексной даты (дата операции/биопсии), дата рождения → возраст;
FR-1.5 отчёт с обязательным подтверждением; FR-1.6 исходник и его метаданные не сохраняются; квазиидентификаторы
(точный возраст, возраст ≥ 90, длинные числовые коды) выносятся на ручную проверку; FR-1.9 таблица «случаи ×
признаки» с подсветкой пропусков и нераспознанных значений, ручным редактированием и ссылкой на источник
(файл, строка); FR-1.11 словарь данных (тип, группа, уровни/порядок, включение), нормализация значений
(+/−, да/нет, pos/neg, G1–G3, 0/1+/2+/3+, pT, стадии, низкий/умеренный/высокий); FR-1.12 экспорт таблицы.

**Модуль 2 — анализ.** FR-2.1 «Таблица 1»; FR-2.2 попарные ассоциации с выбором теста по типам из словаря
(Fisher 2×2 и R×C, χ² при n ≥ 30, Mann–Whitney, Kruskal–Wallis, Spearman); эффекты с 95% ДИ (OR по Вульфу с
поправкой Холдейна, сдвиг Ходжеса–Лемана, ε², V Крамера, ρ — bootstrap/Fisher z); FR-2.3 иерархическая
кластеризация по расстоянию Гауэра с тепловой картой и bootstrap-устойчивостью (Jaccard); FR-2.5 выбросы,
нетипичные иммунофенотипы, взаимоисключение/ко-встречаемость альтераций, oncoprint; для n < 10 — общие и
различающиеся признаки случаев; FR-2.7 карточки находок в формате PRD 2.3 (утверждение, статистика,
ограничения, в т.ч. возможные смешивающие факторы, иллюстрация, код); FR-2.8 графики; FR-2.9 логика
«данные → метод → почему» + интерпретация Claude по кнопке; FR-2.10 экспорт скрипта анализа (.zip);
FR-2.11 журнал всех гипотез, включая незначимые и не выполненные из-за guardrails; FR-2.12 своя гипотеза
на естественном языке.

**Модуль 3 — литература.** FR-3.1 загрузка PDF (текстовый слой, разделы, страницы; References не
индексируются); FR-3.2 добавление по DOI/PMID с полным текстом из PubMed Central (JATS), затем Unpaywall,
затем abstract PubMed; FR-3.3 сверка метаданных PDF с Crossref/PubMed (DOI из текста или поиск по первой
странице, проверка названия; ручное исправление DOI/PMID); FR-3.4 извлечение тезисов (дизайн, n, маркеры и
альтерации с частотами, находки, ограничения) — каждый пункт с цитатой, числа должны встречаться в цитате;
FR-3.5 база фрагментов с источником, страницей и разделом, поиск BM25 с синонимами маркеров; FR-3.6 матрица
литературы со строкой собственной серии; FR-3.7 и FR-2.6 сопоставление каждой находки с базой: статус
(описано / противоречит / только малые серии / не описано), сводка, цитаты, формулировка новизны с
подтверждением автором; строка «Литература» в карточке находки; FR-3.8 расстановка цитат в тексте
(по предложениям: цитата / собственный результат / общее знание / нужен источник); FR-3.9 независимая
проверка цитат (supported / partial / not supported), принятие/отклонение автором, неподтверждённые
принятые цитаты блокируют экспорт; FR-3.10 список литературы через CSL (Vancouver/NLM, Elsevier Vancouver,
AMA, Springer, Nature, APA, Harvard — стили лежат в `backend/app/literature/csl/`); FR-3.11 проверка полноты
(неиспользованные, дубликаты, неподтверждённые метаданные, только abstract); FR-3.12 поиск в PubMed с
добавлением только по решению автора; FR-3.13 проверка отзыва статей (PubMed + Crossref); FR-3.14 импорт
RIS/BibTeX.

**Модуль 4 — профили журналов.** Страница «Журналы» (база профилей) и шаги мастера 1, 6, 8.
FR-4.1 стартовая база из 7 журналов PRD: в коде и данных — только название, издатель и ссылка на официальные
guidelines (`backend/app/journals/starter.json`); значения требований не хардкодятся. FR-4.2 профиль любого
журнала: текст guidelines по URL, из PDF или вставкой (сайты издателей обычно закрыты от автоматической
загрузки — защиту от ботов приложение не обходит), извлечение моделью по каталогу из ~115 полей (структура и
лимиты по типам статей, abstract, ключевые слова, стиль цитирования, рисунки, обязательные заявления, политика
по ИИ, чек-листы отчётности, cover letter) — каждое значение с дословной цитатой, которая сверяется с текстом;
поля без цитаты помечаются, не найденные — явно «нет в guidelines»; ручные значения автора не перезаписываются.
Подтверждение человеком фиксирует кто, когда, URL и версии текста; профиль с непроверенными полями подтвердить
нельзя. FR-4.3 версии профиля и история, перепроверка guidelines с построчным diff, статус «устарел» через 90
дней и «изменён после проверки». FR-4.4 шаблон рукописи по профилю и типу статьи (шаг 6), выбор журнала в
проекте автоматически скачивает и применяет его CSL-стиль (включая зависимые стили репозитория CSL). FR-4.5
индикатор лимитов, FR-4.6 чек-лист перед подачей (шаг 8) с автоматическими, ручными и ожидающими модуля 5
пунктами; блокирующие пункты отмечены. Схема полей — `backend/app/journals/schema.py`.

**Модуль 5 — генерация статьи** (шаги 7 и 10). Числа в тексте — только ссылки на лист фактов анализа
(`{{A1.p_expr}}`, `{{V2.median}}`, `{{TAB:t1}}`), значения подставляет код; число, набранное вручную, либо
совпадает с фактом (предупреждение «замените ссылкой»), либо не найдено в результатах (в Results/Abstract —
блокирует экспорт, пока автор не отметит «проверено вручную»). Порядок работы: терминология (английские
названия признаков и значений), данные автора для Methods и заявлений (клоны, разведения, платформы, этика,
CRediT), план с ключевыми сообщениями, тезисами и бюджетом слов (FR-5.1, согласуется до генерации), таблицы и
рисунки из результатов анализа (FR-5.6, 5.7), разделы по очереди: черновик агента → правка в редакторе
(вставка чисел, цитат, ссылок на таблицы) или инструкция агенту к выделенному фрагменту → принятие (FR-5.2);
Abstract собирается после принятия Results и Discussion. У каждого раздела — все версии с diff и откатом
(FR-0.3), комментарии, пометка «требует обновления» при изменении находок, анализа, литературы или данных
автора (FR-0.4, 5.12). Introduction и Discussion пишет агент с поиском по базе литературы; новые цитаты
проходят дословную сверку и независимую проверку, непроверяемые заменяются на «[уточнить: источник]».
Проверки (PRD 5.4): неизвестные ссылки, «[уточнить: …]», статус цитат, ИИ-клише (пополняемый стоп-лист
`data/cliches.json`), сила формулировок относительно уровня доказательности, аббревиатуры, согласованность
написаний, UK/US, абзац ограничений в Discussion, кириллица в тексте, таблицах и подписях. Заявления
(FR-5.10) и AI-use disclosure (FR-7.1) формируются из данных автора и фактического журнала обращений к
моделям. Экспорт (FR-5.13): .docx (Times New Roman 12, двойной интервал, нумерация строк и страниц), .md,
рисунки в формате и dpi профиля журнала с английскими подписями, supplementary (таблица случаев, скрипт
анализа, журнал гипотез). Черновик — всегда, с пометкой DRAFT и списком вопросов; пакет для подачи — только
без блокирующих проблем (включая чек-лист журнала). Индикатор лимитов и чек-лист модуля 4 берут значения из
рукописи.

**Модуль 6 — cover letter** (шаг 9). Пишется после финализации статьи (выбрано название, принят Abstract;
FR-6.1). Адресат — главный редактор из профиля журнала (редактируется), тон формальный или более
персональный (FR-6.4). Модель пишет только тело письма: название и тип статьи, соответствие scope журнала,
ключевые находки с формулировками по уровню доказательности, заявления об оригинальности, отсутствии
параллельной подачи, одобрении всеми авторами и конфликте интересов (FR-6.2), требования журнала к cover
letter с отчётом, где каждое учтено (FR-6.3). Обращение, списки предлагаемых и исключённых рецензентов
(FR-6.5) и подпись собирает код — имена и e-mail в модель не передаются. Проверки: обязательные заявления,
совпадение названия, «hype»-формулировки, «significant» при exploratory-находках, незаполненные места,
подпись; каждое требование журнала подтверждает автор. Версии с diff и откатом, правка по инструкции,
принятие; упрощённая версия для переподачи (поле «перевод из другого журнала», FR-6.6). Письмо входит в
пакет экспорта (`cover_letter.docx`) и закрывает пункт чек-листа журнала; без принятого письма пакет для
подачи не выгружается.

**Модуль 7 — этика и прозрачность** (шаг 8, вкладка «Этика и прозрачность»). FR-7.1: журнал фактических
обращений проекта к моделям (задачи, модели, объём — без содержимого) и собранное из него заявление об
использовании ИИ с требованием и политикой журнала. FR-7.2: ИИ-инструмент в списке авторов блокирует экспорт.
FR-7.3: этические требования с учётом типа статьи и размера серии (одобрение комитета, согласие на
публикацию — для case report и серий ≤ 5 — письменное, фото, подтверждённая анонимизация, политика по ИИ).
FR-7.4: риск реидентификации в тексте (предложения с ≥ 3 квазиидентификаторами: точный возраст, пол, дата,
место, конкретный вариант, профессия; для case report и n ≤ 5 — с 2) и в данных — k-анонимность
supplementary-таблицы по возрасту, полу, локализации и редким вариантам с обобщениями, которые применяются в
экспорте (возраст диапазонами 5/10/20 лет, исключение столбцов; свободный текст, внутренние ID и любые
столбцы, похожие на идентификаторы, не выгружаются никогда). FR-7.5: дословные совпадения текста рукописи и
cover letter с фрагментами базы литературы (8-граммы слов; ≥ 12 слов — предупреждение, ≥ 25 — блокирует
экспорт; текст в кавычках не учитывается). Все проверки модуля входят в статус экспорта.

**Инфраструктура MVP.** Аутентификация (NFR-5): e-mail и пароль (scrypt), сессии в HttpOnly-cookie,
TOTP-2FA с QR-кодом, блокировка после 5 неудачных попыток, CSRF-заголовок, доступ к проектам только по
членству (default deny), роли владелец / редактор / комментатор, профили журналов: стартовые изменяет
администратор, пользовательские видит только автор. Шифрование при хранении (NFR-1, 4): AES-256-GCM, ключ
на проект, обёрнутый мастер-ключом, путь файла как associated data (подмена файлов обнаруживается),
удаление проекта уничтожает ключ; существующие проекты шифруются при запуске. БД на SQLAlchemy: SQLite
локально, PostgreSQL 16 в проде (весь набор тестов проходит на обоих); журнал обращений к LLM — в БД,
только метаданные (NFR-7). Фоновые задачи (NFR-14): долгие операции уходят в очередь в БД, выполняются
воркером от имени того же пользователя, прогресс виден и после перезагрузки страницы. Песочница анализа
(NFR-6): расшифрованные файлы только во временном каталоге на время запуска; в развёртывании — отдельный
контейнер без сети. NER-анонимизация (Natasha, русский) поверх правил с защитой эпонимов; места и
организации — на ручную проверку. Evals (NFR-15): полнота удаления идентификаторов на синтетическом наборе
— 92,4 % правилами и 100 % с NER, медицинский текст сохраняется на 100 %; прогон нашёл и закрыл две утечки
(даты в конце предложения, ФИО в косвенных падежах). GROBID для PDF статей (с откатом на pypdf),
заголовки безопасности (CSP, HSTS), docker-compose с изолированными сетями и TLS — см. docs/DEPLOY.md.

## Что дальше (PRD раздел 10)

Все модули P0 и основные P1 модуля 7 реализованы на уровне прототипа. Остались пункты P1/P2: микрофото и
панели (FR-5.8), чек-листы CARE/REMARK/STROBE (FR-5.11),
анализ выживаемости (FR-2.4), response to reviewers (FR-6.6), совместная работа и SSO (FR-0.6, NFR-5), а
также инфраструктура MVP: PostgreSQL + pgvector, очередь задач, шифрование, аутентификация, NER-анонимизация,
GROBID.

Ограничения прототипа, которые нужно закрыть до работы с реальными данными пациентов:

- анонимизация: NER только для русского (английские имена ловят правила); критерий приёмки PRD на 50
  реальных заключениях ещё не прогонялся — evals синтетические;
- Docker-образы и compose не собирались (нет Docker на машине разработки); локально песочница — отдельный
  процесс без сетевой изоляции;
- векторный поиск (pgvector) ждёт выбора провайдера эмбеддингов; фронтенд остаётся на чистом JS (Next.js
  из PRD — при появлении сборки);
- извлечение данных из свободного текста заключений (.docx/.pdf, FR-1.7) и режим case report (n = 1) — в MVP;
- открытые вопросы PRD (раздел 11: юрисдикция, хостинг, провайдер LLM с ZDR) не решены;
- литература: поиск лексический (BM25), в MVP — гибридный с эмбеддингами в pgvector; разбор PDF эвристический
  (pypdf), в MVP — GROBID; сканы без текстового слоя не поддерживаются; просмотр PDF открывает файл, но пока
  без подсветки цитируемого фрагмента; citeproc-py оформляет дату только годом;
- журналы: профили стартовой базы пусты — их нужно заполнить по актуальным guidelines и подтвердить (это
  требование PRD); перепроверка по расписанию и уведомления (FR-4.3) — вручную кнопкой; профили общие для
  всех пользователей (FR-4.7, P2);
- рукопись: .docx собирается python-docx (Pandoc из PRD не используется — не нужен внешний бинарник);
  редактор — текстовое поле с разметкой ссылок и предпросмотр (TipTap/ProseMirror — при переходе на Next.js);
  микрофото и панели (FR-5.8), чек-листы CARE/REMARK/STROBE (FR-5.11) — P1; генерация идёт синхронно.

Модели настраиваются переменными окружения: `AI_ARTICLE_MODEL_REASONING` (по умолчанию `claude-opus-5-5` —
интерпретация) и `AI_ARTICLE_MODEL_EXTRACTION` (`claude-sonnet-5` — разбор вопросов), как в PRD 8.3.
Каталог данных — `AI_ARTICLE_DATA_DIR` (по умолчанию `./data`). `AI_ARTICLE_CONTACT_EMAIL` включает поиск
OA-версий через Unpaywall и передаётся в PubMed/Crossref как контакт (их рекомендация); `NCBI_API_KEY`
повышает лимит запросов к PubMed.

Во внешние библиографические сервисы уходят только DOI/PMID и поисковые запросы автора. В Claude при
сопоставлении находки уходит карточка находки (агрегированные числа) — только после подтверждения
анонимизации; при чтении статей — текст опубликованных статей.
